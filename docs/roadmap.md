3. 对照全论文逐项验收，记录指标偏差、适配器、生成参数和硬件差异。软件测试通过或单一指标接近都不等于科研验收通过。
4. 验收后冻结代码提交、数据与模型哈希、结果和运行配置，再创建 `feat/degradation-risk-router`。

当前没有已验收的科研冻结点，不创建声称基线已完成的新算法分支。既有 CPU 原型及开发集准备保留在 [扩展历史记录](archive/degradation-risk-plan.md)，暂停推进。
